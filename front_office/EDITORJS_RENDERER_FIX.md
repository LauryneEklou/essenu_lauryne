# EditorJS Renderer Fix - Documentation

## Problem Statement

**Issue Title**: "editorjs-renderer.js n'agit pas sur +article-featured"

The EditorJS renderer script was not properly targeting and enhancing content rendered by the `+article-featured` Pug mixin.

## Root Cause

The issue occurred because of a **DOM selector mismatch**:

### Before (Problematic)
The `editorjs-renderer.js` script was likely using selectors like:
- `#editorjs` (ID selector)
- `[data-editorjs]` (attribute selector)
- `.editor-content` (generic class)

### The Problem
The `+article-featured` mixin was outputting content with a different class/structure, so the JavaScript couldn't find and enhance it.

## Solution

### 1. Standardized CSS Class
The `+article-featured` mixin now wraps EditorJS content in a container with the class `.editorjs-output`:

```pug
.article-content.editorjs-output
  != article.description
```

### 2. Updated JavaScript Selector
The `editorjs-renderer.js` script now explicitly targets `.editorjs-output`:

```javascript
const editorjsContainers = document.querySelectorAll('.editorjs-output');
```

### 3. Multiple Container Support
The renderer now handles multiple EditorJS content blocks on the same page:

```javascript
editorjsContainers.forEach((container, index) => {
    enhanceEditorJSContent(container, index);
});
```

### The +article-featured Mixin

```pug
mixin article-featured(article)
  article.article-featured(data-article-id=article.id)
    .article-header
      h1.article-title= article.title
    
    .article-content.editorjs-output
      //- CRITICAL: The .editorjs-output class is the key!
      != article.description
```

**Key Points:**
- Uses `!=` to output unescaped HTML (since backend already converted EditorJS to HTML)
- Applies `.editorjs-output` class for JavaScript targeting
- The `article.description` contains HTML generated by the backend's `renderEditorJsToHtml()` function

### The editorjs-renderer.js Script

```javascript
function initializeEditorJSRenderer() {
    // Target ALL elements with .editorjs-output class
    const editorjsContainers = document.querySelectorAll('.editorjs-output');
    
    editorjsContainers.forEach((container, index) => {
        enhanceEditorJSContent(container, index);
    });
}
```

**Enhancements Applied:**
1. **Responsive Images**: Ensures images scale properly
2. **Interactive Images**: Click-to-zoom functionality
3. **List Styling**: Proper indentation and spacing
4. **Blockquote Styling**: Visual left border and italic text
5. **Code Block Styling**: Background color and syntax highlighting preparation
6. **Table Responsiveness**: Wraps tables in scrollable containers

## Backend Integration

The backend (in `/api/front_office/src/controllers/new.controller.js`) already handles EditorJS to HTML conversion:

```javascript
function renderEditorJsToHtml(blocks){
    if(!Array.isArray(blocks)) return '';
    return blocks.map(b => {
        const type = b.type;
        const d = b.data || {};
        if(type === 'header'){
            const level = d.level || 2;
            return `<h${level}>${String(d.text || '')}</h${level}>`;
        }
        if(type === 'paragraph'){
            return `<p>${String(d.text || '')}</p>`;
        }
        // ... more block types
    }).join('');
}
```

**Flow:**
1. Content stored as EditorJS JSON in database
2. Backend converts JSON to HTML using `renderEditorJsToHtml()`
3. Frontend receives HTML in `article.description`
4. Pug mixin renders HTML with `.editorjs-output` class
5. JavaScript enhances the rendered HTML

## Testing

### 1. Check Rendering

Open browser console and verify:

```javascript
// Should find the container
document.querySelector('.editorjs-output')

// Should be marked as enhanced
document.querySelector('.editorjs-output[data-enhanced="true"]')
```

### 2. Check Enhancements

Verify that:
- Images have `max-width: 100%`
- Lists have proper margins
- Blockquotes have left border
- Code blocks have background color
- Container has `editorjs-enhanced` class

### 3. Debug Logging

The script includes console logging:

```
[editorjs-renderer] Found 1 EditorJS container(s)
[editorjs-renderer] Enhancing container #0
```

If you don't see these messages, check that:
1. The script is loaded correctly
2. The `.editorjs-output` class exists in the HTML
3. The script runs after DOM is ready

## Common Issues and Solutions

### Issue 1: Script doesn't run
**Solution**: Ensure script is included AFTER the content in the HTML, or wait for DOMContentLoaded

### Issue 2: Multiple containers not enhanced
**Solution**: The script now uses `querySelectorAll()` to handle multiple containers

### Issue 3: Styles not applying
**Solution**: Check that the script completed successfully and added the `editorjs-enhanced` class

### Issue 4: Script runs but content not found
**Solution**: Verify the mixin uses `.editorjs-output` class and content is actually rendered
